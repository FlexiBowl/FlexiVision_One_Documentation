# Working in this repository

Sphinx + MyST technical manual for **FlexiVision One**, published automatically to
https://flexivision-docs.flexibowl.com.

## Layout

- `sources/` — the manual. Edit here.
- `build/` — generated HTML. **Never hand-edit**; regenerated by `build_manual.bat`.
- `tools/manual_publisher/` — the build pipeline.

## Media

- Video, GIF, PDF and archives route through Git LFS automatically via
  `.gitattributes`. Install Git LFS before committing media.
- CI rejects any tracked file over 10 MB that isn't in LFS.
- Don't commit heavy binaries (raw CAD exports, full-resolution photos) straight into
  `sources/`; shrink anything over a few MB first.

## Never commit

- `.tmp_manual_build_*/` — scratch dirs left by interrupted builds. Gitignored;
  delete on sight, they can be tens of GB.
- `DEPLOY_SETUP.md` — internal infrastructure notes. Gitignored.

## Deployment

- Pushing to `main` **deploys to production** within 1–2 minutes.
- Deploy infrastructure is owned by Makai Labs, not ARS — don't change without
  asking: `Dockerfile`, `nginx.conf`, `.dockerignore`, `.gitattributes`,
  `.github/workflows/**`.

## Sibling repository

`FlexiBowl_Documentation` is the companion manual, deployed independently to its own
subdomain (`flexibowl-docs.flexibowl.com`). It shares tooling and conventions with this
repo — the rules above apply there too, and a change to shared tooling usually belongs
in both.
